# 有人云巡站客户端（Windows / macOS）

[有人云](https://www.usr.cn) 平台的第三方桌面客户端：批量巡检设备、自动截图归档、
离线/数据陈旧告警、历史数据留档。界面是本地网页，不用装浏览器插件。

> 本仓库是**干净版本**：不含任何账号、密码、登录缓存、巡检截图与历史数据，
> 也不含任何公司标识。克隆下来后需要自己添加账号。

当前版本 **v1.4.3**。

## 〇、功能

- **巡站**：按账号批量巡检设备，一台一张卡片图存档，跑完自动打包 zip；
  没取到的站可以只补跑这几台，单张图也能重拍
- **监控**：后台常驻，按规则比对并推系统通知，离线 / 数据陈旧 / 恢复都提醒，重复告警去重；
  **点通知可跳转到对应站点**
- **数据时间**：列表与实时卡片上的「X 分钟前」按当前时钟**实时走动**，在线 / 数据陈旧也随当前时钟复判，
  不会停在上一轮巡检的旧时间上
- **控制下发**：可写变量（写数值 / 开关）支持下发，**二次确认**后才真正发到设备
- **历史**：自动采样留档，可按账号 / 设备查历史值；折线图横轴按所选范围铺满，跨天按日期标刻度，
  鼠标悬浮可看每个点的确切时间与数值，只有真离线才断线
- **设备列表**：支持排序与按账号搜索；**复制站点名称**一键进剪贴板；
  常看的站点可以**置顶**，固定排在最前
- **单个变量刷新**：只重采某个变量，不重绘整页
- **右键菜单**：输入框有剪切 / 复制 / 粘贴 / 全选；站点、设备行上有「复制站点名称」
  「置顶该站 / 取消置顶该站」「刷新这台设备的实时数据」
- **关于页**：显示版本、本次新增，以及 **GitHub 项目地址入口**（点击用系统浏览器打开）

## 一、更新记录

### v1.4.3 修订（版本号不变）

**一、取数方式改了，弱一点的网络也能跑完整。**
以前每台设备要挨个问好几样东西，设备一多，就有相当一部分拿不到值 ——
而拿回来的还是空数据，跟「设备真的没数据」长得一模一样。现在一轮里的来回少了很多，
变量名单问过一次就不再重复问，速度也快了一截。
万一这一轮还是没拿到，隔一小会儿会自己再跑一次，不再白等半小时留下一整片空白。

**二、「没问到」不再等于「离线」。**
有时候请求会被拒绝，而且拒绝得很安静：返回里没有数据，外形与「设备确实没数据」完全一样。
以前这种情况直接判成「设备离线、变量全是 -」。现在新增一个「未取到」状态：
界面显示上一轮的数值，加一行橙色原因，**不报警、不改状态**；从来没成功过的设备记「未巡」，
不凭空判离线；截图上的徽标也写「未取到」。
一批里只有少数几台没权限时，只有它们受影响，其余照常出图；登录过期会自动重登一次，
多个任务同时撞上只登一次。

**三、只补跑没数据的站。**
巡站页新增「只跑没数据的 N 台」，只跑离线 / 采集异常 / 未取到的（数据陈旧算有数据）。
补跑仍然算同一个批次：图片同名覆盖、报告就地合并、压缩包重打同名，不会多出第二个「同一批」的包，
「报告条数 = 图片张数 = 压缩包里张数」照样对得上，没跑的那几十台原样保留、位置不动。
定位按设备编号而不是站名 —— 一个工区常有好几个同名站，按名字会盖掉别人的条目。

**四、单张重拍。**
截图弹窗新增「⟳ 重新获取这张截图」：只重跑这一台，后台跑、界面不冻，不影响整批的状态。
拍失败不写报告、不删旧图，界面继续显示原来那张。整批正在跑时不允许重拍，
免得两边同时写报告，刚重拍的又变回旧的。

**五、账号行的台数统计一直是错的。**
以前不管实际什么状态，最后都被算成离线。现在在线 / 数据陈旧 / 离线 / 采集异常 / 未取到分开统计。

### v1.4.3 新增

**一、默认开硬件加速，崩过才降级。**
以前为了躲部分机器上「GPU 起不来、整个程序退出」的问题，默认关掉硬件加速，整页合成全走 CPU，
长列表滚动和拖分栏都有点发涩。现在默认开硬件加速，只有**本机真崩过**才转软件渲染：
反复崩溃就自动降级并重启；过一段时间再试着开回硬件，还不行就把重试间隔拉长，最长两个月试一次。
这样能用的机器用上加速，不行的机器也不会反复崩。

**二、三栏宽度可以拖。**
账号栏和右侧栏之间那条分隔线可以拖动：鼠标压上去变蓝、浮出三个点当抓手。拖宽一栏另一栏自动让位，
中间设备列表保底不被挤爆；双击复原，宽度下次打开还在。

**三、实时卡能搜变量了。**
一台设备能有三四百个变量。实时卡顶部加了搜索条，固定在卡片外不随内容滚走，输入即过滤，
右侧显示「命中 / 总数」，一个都不匹配时给提示而不是留白；Esc 或 ✕ 清空，换设备自动清空。
过滤不会打断后台刷新，也不会冲掉正在输入的值。

**四、实时卡刷新改成原地更新。**
以前每次刷新整张卡重画一遍，几百行要重排一次，后台每隔几秒刷一次，界面就每隔几秒卡一下，
滚动位置还会跳。现在只改数值、单位、上报时间、状态这几格；用户正在某一格输入时不覆盖。

**五、变量名不再被截断。**
可写行右侧的按钮占了不少宽度，「压缩机1运行状态」被截成「压缩机…」。现在行高由内容撑开，
名字放不下就折第二行，两行字数尽量接近。

**六、变量置顶修「同类交错」。**
关键词「出水温度」也会命中「风机化霜出水温度1」，两段混在同一个名次里，
置顶的四条被同类变量隔开。现在完全等于关键词的排第一段、只是包含的排第二段，四个温度先排完。

**七、顺手两处。**
右栏拖宽后卡片不再靠左留白；日志框只留最近 400 行，不再堆上万行；日志时间改用本机时间
（原来差 8 小时）。

### v1.4.2 新增

**一、左栏账号上的台数按当前站点筛选算。**
原来那个数取的是「上次巡站报告的总台数」，改完站点过滤不会变，看着就像「加了 15 个站，还是 72 台」。
现在按手里已有的设备清单和最新的账号表本地数一遍，筛选一改立刻就对。
和上次巡站不一致时，副标题会写成「78 台 · 上次巡站 在线 70 / 离线 8」，悬停能看到两个数各自的口径。

**二、改了账号表不用重启。**
账号表是纯文本，可以直接用系统编辑器改（也可以在另一个窗口改）。界面会自己发现改动，
自动重画账号列表并刷新设备列表，不用等一会儿、也不用切页。
以前只有在本页点保存才认。

**三、实时卡每行多一列「最后上报时间」。**
以前每行写死「刚刚」，既对不齐也看不出真实时刻。现在显示这一路实际的上报时间：
当天 `15:42`、跨天 `10-19`，悬停看完整时间（到秒）。固定宽度右对齐成一列，
哪一路没在更新，扫一眼就知道。单独刷新某一行时只更新这一格，不整块重画。

### v1.4.1 新增

**一、变量可以置顶了。**
变量的显示顺序以前跟着平台返回走，同一台设备的「出水温度」和「进水温度」位置会来回跳。
现在固定成一张顺序表，默认：出水温度 → 进水温度 → 供水温度 → 回水温度。
数据监控、巡站截图、历史数据用的是同一份顺序；「设置 → 变量置顶」可以自己加关键词、
上下调整、取消勾选，改完立即生效。
名字里带「修正 / 设定 / 原值 / 系数 / 补偿 / 偏置」的不参与排前
（`回水温度修正`、`水温设定` 这类是参数，不是读数）。

**二、站点可以置顶了。**
设备列表里右键 →「置顶该站」，或在「设置 → 置顶站点」搜出来添加，两处是同一份数据。
巡站、数据监控、历史数据三个列表都按这个顺序排，点表头升降序也不会把置顶的站挤下去。
置顶区第一台会默认选中，取消置顶后回到原来的位置。

**三、修了一个显示问题。**
「设置 → 关闭按钮」以前看不到当前选的是哪一项，现在打开就显示真实值。

### v1.3.0 新增

**历史折线图重做。** 原来的图有三个说不通的地方，毛病是同一个 —— 把「有数据的范围」当成了「用户选的范围」：

- **横轴只框住有数据的那一小段**。选「近 7 天」而本地记录只攒了 22 小时，横轴就缩成小时尺度，
  几天的空白被压成几小时，稀疏点之间再拉直线，看着像连续数据。现在横轴一律按所选范围铺满，
  没数据的区域就空着 —— 空白本身也是信息（那段时间没有上报）。
- **跨天不按日期标刻度**。旧逻辑超过 3 天才标日期，选「近 3 天」时横轴还是小时刻度，
  一天里的哪个时刻根本对不上。现在两天以上就按日期标，天数多自动隔几天取一格；一天以内按时刻均分。
- **断线太随意**。本地和云端都按「值没变就不记」瘦身，单看一个变量的缺口根本分不清
  「值没变」和「设备离线」，旧写法按固定间隔硬断，把一台设备好好的出水温度曲线撕成了 4 截。
  现在按证据判：缺口在正常节奏内就画连；同一轮里其它变量有记录，说明这路只是值没变，也连；
  程序在跑、这台设备却没任何记录，才断；程序当时也没开，就没证据，短缺口猜它连着、长缺口断开。

配套两处小东西：**鼠标悬浮可看每个点**（多天尺度上稀疏点对不上刻度，得能逐个问出确切时间与数值）；
记录还没攒够所选范围时，标题栏标一句「数据自 MM-DD HH:MM」，否则用户会以为图画错了。
「无数据」只标在没有线的地方 —— 设备活着、只是值没变被瘦身的空缺不标，那儿有线，标了自相矛盾。

**「并发线程」一处设置管两处。** 设置页这个数以前只管巡站截图，后台监控巡检自己按 3 跑：
把设置调到 6 或 8，后台还是老速度，看着就是「设置没生效」。现在改完立即同步给后台巡检；
跑截图时状态栏显示「截图中 3/46 · 6 线程」，启动日志里也打印一行，实际生效值看得见。
顺带修掉一个会把设置改回默认的问题：以前某些操作会把你存好的 6 悄悄改回 4。

### v1.3.0 修订（版本号不变）

**截图卡片把水温变量排到最前。** 每台设备只画前 10 个变量，顺序是平台返回的原始顺序，
一台 17 个变量的机组，前十个位置常被水流量、定时运行使能、启动信号占满，
**供水 / 回水温度落在第 13、14 位，直接被截掉，截图里干脆没有温度**。

现在渲染前先按「水温优先」重排再截断，分三档（同档内保持平台原顺序）：

| 档 | 什么算 | 例子 |
| --- | --- | --- |
| 0 · 水温 | 名字里既有「水」又有温度字样 | 供水温度T1、回水温度T2、水温、水箱温度、循环水温度 |
| 1 · 其它温度 | 名字里有「温度」或以「温」结尾 | 室内温度T3、室外温度T4 |
| 2 · 其余 | 以上都不是 | 水流量、循环泵出口压力、定时运行使能 |

**先排序再截断** —— 搞反了等于没改，水温变量早在第 11 位就被扔掉了。
**只看变量名不看单位**，单位那列空值、异常格式都得兜，而问题本来就出在名字上。
**设定值和工程参数不算水温**：`水温设定`、`制冷停止温度`、`T1修正` 都留在原位置，
`水流量`、`水压` 只有水没有温，也不进第 0 档。
有浏览器和无浏览器环境看到的是同一个顺序。

### v1.2.0 新增

**「数据时间」改成按当前时钟实时走动。** 以前「X 分钟前」是巡检那一刻算好的静态值：
10:30 巡检算出「1 分钟前」，到 11:00 界面上还写着「1 分钟前」。巡检 30 分钟一轮，
设备明明半小时没更新，看上去永远新鲜。

现在按本机时钟现算，列表和实时卡片里的时间会真的往上爬。配套两处：
- **状态同步复判**：按当前时钟再判一次，越过「数据陈旧」阈值就从「在线」改写过来，
  不会再出现「在线 11 小时前」这种自相矛盾。阈值改完保存立刻生效。
- **刷新成功即刷新时间**：单独刷新读到值的瞬间，时间就跟着变成「现在」，不会刚刷到新数据还挂着旧时间。

排序也改用复判后的状态与实时时间，避免「显示数据陈旧、却按在线排在最前」。

## 三、从源码运行

需要 **Python 3.11+** 和 **Node.js**（仅用于装 Electron）。

```bash
# 1) Python 依赖
pip install pillow requests paho-mqtt

# 2) Electron（国内建议走镜像）
set ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/   # Windows
export ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/  # macOS / Linux
npm install

# 3) 启动
npm start
```

启动后先在「账号」页添加账号：名称 / 账号（手机号）/ 密码 / 平台 ID（默认 `W3rfV`）/
站点过滤（留空＝该账号全部设备）。

## 四、使用免安装包（推荐）

Release 里给的是**免安装版**，解压即用，不需要装 Node.js 和 Python：

| 文件 | 平台 | 怎么用 |
| --- | --- | --- |
| `usrcloud-patrol-client-Windows-x64.zip` | Windows 10/11 x64 | 解压后双击 `有人云巡站客户端.exe` |
| `usrcloud-patrol-client-macOS-arm64.zip` | Apple Silicon Mac | 解压后把 `.app` 拖进「应用程序」，首次打开**必须右键**（见下一节） |

两个包都**自带 Python 运行时**（含 pillow / requests / paho-mqtt），不依赖系统里装的 Python。
Windows 版放在 `resources/app/python/`，macOS 版放在 `Contents/Resources/app/python/`；
只有找不到内置运行时才回落到系统 `python3`。

### macOS 未签名，首次打开怎么过门禁

本项目的 Mac 包**没有苹果开发者签名**（没有交 99 美元/年的开发者账号费用），
所以 macOS 的 Gatekeeper 会拦截，表现是双击后弹：

> 「有人云巡站客户端」已损坏，无法打开。您应该将它移到废纸篓。

**这不是文件损坏，也不是病毒**，只是系统不认识开发者。三种办法任选：

**办法一（推荐，最省事）**
1. 在访达里找到 `有人云巡站客户端.app`
2. **右键**（或按住 Control 点）→ 选「打开」
3. 弹窗里点「打开」

只需要做这一次，之后双击就能直接启动。

**办法二（用包内脚本）**
双击 zip 解压出来的 `解除门禁.command`，它会自动对 app 做一次去隔离属性处理。

**办法三（命令行）**
```bash
xattr -dr com.apple.quarantine "/Applications/有人云巡站客户端.app"
```

如果还想手动确认，可以看下签名状态：
```bash
spctl -a -vv "/Applications/有人云巡站客户端.app"
# 输出 "rejected" 是正常的，说明只是没签名，不是被判定为恶意软件
```

> 说明：只有从网上下载的 app 会被打上隔离属性（quarantine）。
> 自己编译的、或用 U 盘拷的，通常不会触发这个提示。

## 六、自行打包

1. 下载对应平台的 Electron 运行时（`electron-v44.5.1-win32-x64.zip`、`electron-v44.5.1-darwin-arm64.zip`）
2. 把源码放进 Electron 的 `resources/app/`
3. Windows 版额外把 Python 运行时放到 `resources/app/python/`
4. 改 exe / app 名与图标即可分发

## 七、版本号

桌面端的版本号只有一处真源：`package.json` 的 `version` 字段。

| 位置 | 字段 | 当前值 |
| --- | --- | --- |
| `package.json` | `version` | `1.4.3` |
| Git tag / Release | 标签名 | `v1.4.3` |
| 界面「设置 → 关于」 | 显示版本 | 与上面一致，写全三位 |

发版时保持三者一致即可。
